# HomeCloudBackend — Storage filesystem scan v1

`storage.files.list` выводит **только управляемые объекты** из SQLite (`hc_storage_files`).
Она не показывает посторонние документы, существовавшие на диске до регистрации.

`storage.scan` выполняет **сканирование файловой системы в режиме только чтения**.
Ничего не удаляет, не перемещает и **не импортирует** в SQLite. Не меняет `storage.files.list`.

## STORAGE.SCAN — все доступные файлы NFS

На подключении `/ws`, после `hello`:

```json
{
  "v": 1,
  "id": "nfs-scan-001",
  "type": "command",
  "action": "storage.scan",
  "data": {
    "storage_id": "50fefe420c21a7050550ac1b33c17713",
    "recursive": true,
    "limit": 30
  }
}
```

Ответ `type: result` содержит `files_count`, `directories_count`, `symlinks_count`,
`total_bytes`, `complete`, `error_count`, `errors`, `entries` и
`entries_truncated`.

- `recursive` по умолчанию `true`, `false` — только корень и имена подкаталогов.
- `limit` по умолчанию 30, максимум 100; ограничивает только возвращаемый список
  путей, а **не** подсчёт файлов.
- `.homecloud/` в корне тома пропускается, чтобы не учитывать наши внутренние `.bin`
  и временные `.part` как обычные документы.
- Сканер не вычисляет SHA-256 всех файлов: это прочитало бы гигабайты данных
  по NFS без необходимости.
- Строгий лимит прохода: 100 000 элементов и приблизительно 15 секунд. Если достигнут
  лимит или возникают ошибки, `complete:false`; итоговые счётчики неполные.
- Символьные ссылки не раскрываются и не обходятся.

**Важно про Windows NFS:** у Linux допустимы имена с символом `:`
(например `*:Zone.Identifier`), а у Windows этот символ специальный.
Если Windows NFS-клиент не способен перечислить каталог, `storage.scan`
может получить неполный результат. Go-программа, выполняющаяся на Windows,
не может перечислить то, что не отдаёт ей операционная система.
Полный каталог Linux лучше сканировать через будущий Go-агент **на Linux-сервере**.

В v1 существующие файлы NFS **не становятся доступны** через
`storage.download.prepare` — для этого нужен отдельный индекс внешних файлов
и контролируемый доступ по путям.
